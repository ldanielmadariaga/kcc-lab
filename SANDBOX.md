# kcc-lab — experimental Config Connector sandbox

**This repository is not for upstream consumption.** It is a personal sandbox for testing
aggressive experimental changes to Config Connector that are not ready for, or not intended
for, `GoogleCloudPlatform/k8s-config-connector`.

Do not file issues here expecting upstream support, and do not treat anything on a topic
branch here as representative of Config Connector behaviour.

## What this repo is for

Running KCC's full regression suite against experimental changes. KCC's presubmit CI is
fully hermetic — every job runs on GitHub-hosted runners against the mockgcp layer, with no
GCP credentials — so the entire suite is portable here with no secret setup.

## Repository topology

| Remote     | Repository                                 | Role                                    |
|------------|--------------------------------------------|-----------------------------------------|
| `upstream` | `GoogleCloudPlatform/k8s-config-connector`  | Read-only source of truth               |
| `origin`   | `ldanielmadariaga/k8s-config-connector`     | Personal fork — the PR bridge upstream  |
| `lab`      | `ldanielmadariaga/kcc-lab`                  | This repo — experimental sandbox + CI   |

`master` here tracks `GoogleCloudPlatform/master` and is kept byte-identical to it apart
from this file. All experimental work lives on topic branches.

Locally, `upstream`'s push URL is deliberately set to an invalid value so `git push upstream`
cannot succeed by accident:

```bash
git remote set-url --push upstream DISABLED_use_origin_fork_instead
```

## Disabled workflows

Three workflows inherited from upstream are disabled here via `gh workflow disable` — repo
configuration that lives outside git, so this repo's tree stays identical to upstream and
port-back diffs carry no sandbox noise:

- `upgrade-operator.yaml` — on a `v1.x.y` tag push it opens a PR **against
  `GoogleCloudPlatform/k8s-config-connector`**. Must stay disabled.
- `review-reminder.yaml` — requires an `EMAIL_SA_KEY` secret not present here, and queries
  the upstream repo.
- `pages-migration-tracker.yaml` — requires GitHub Pages, which is not enabled here.

Check their state with `gh workflow list --all --repo ldanielmadariaga/kcc-lab`.

## Sending changes upstream

Upstream PRs go through the **fork** (`origin`), never from this repo directly.

Keep the fork current, then replay the topic branch onto pristine upstream so no sandbox
commits ride along:

```bash
gh repo sync ldanielmadariaga/k8s-config-connector --branch master
git fetch upstream master
git fetch lab <topic-branch>

git checkout -b port/<topic> lab/<topic-branch>
git rebase --onto upstream/master lab/master port/<topic>
```

Verify the port branch is clean — both must come back empty:

```bash
git diff upstream/master...port/<topic> --stat -- .github/ SANDBOX.md
git log upstream/master..port/<topic> --oneline    # only the intended commits
```

Then run the local gates and open the PR from the fork:

```bash
make fmt && go vet ./... && ./dev/ci/presubmits/validate-generated-files
git push origin port/<topic>
gh pr create --repo GoogleCloudPlatform/k8s-config-connector \
  --base master --head ldanielmadariaga:port/<topic>
```

Contributions upstream require the Google CLA (<https://cla.developers.google.com/>); see
`CONTRIBUTING.md`.

## Guardrails

- Keep anything intended for upstream on its own topic branch, cut fresh from upstream's
  master. A portable fix buried in a branch of aggressive experiments is what makes
  port-back painful — the rebase can only separate what you separated.
- A change is port-ready when `presubmit-gatekeeper` is green on the **rebased** branch, not
  merely on the sandbox branch; this repo's baseline may lag upstream.
- `ci-presubmit.yaml`, `ci-presubmit-bypass.yaml`, `crd-equivalence-check.yaml` and
  `experiments-ci.yaml` are generated by `dev/tasks/generate-github-actions`, and
  `dev/ci/presubmits/validate-github-actions` fails if they drift. Edit the generator, never
  those files directly.
